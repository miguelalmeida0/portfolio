# Dashboard Route Architecture Checklist

Use before implementing complex dashboards and command centers.

- Task inventory exists.
- Route map exists.
- Each nav item has a distinct product job.
- Each route has one primary user question.
- Each route has one primary action or decision.
- Overview, analysis, decision, and action workflows are separated when needed.
- Detail views are focused, anchored, or route-specific.
- Mobile route/mode is real, not only a desktop card.
- Selected nav state changes visible product scope.
- The final dashboard avoids one-page process pileup.

## Blockers

- every workflow lives on one page
- side nav is decorative anchor navigation
- route labels do not change product scope
- mobile flow is represented only as desktop content
- users must parse all processes at once
