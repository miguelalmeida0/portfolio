# Desktop Command Surface Guidance

Desktop command surfaces must preserve the primary product object.

## Rule

A command surface is not a collection of panels. It is a workspace organized around the thing the user manipulates, monitors, or decides from.

Examples:

- Restaurant service app: floor map, seating state, table queue, kitchen/service handoff.
- Dispatch app: live route/map and incident queue.
- Trading/research app: watchlist, thesis object, chart, or signal board.
- Inventory app: item grid, warehouse map, or object detail.

## Required Structure

- One primary product object stays central.
- Supporting panels explain, filter, inspect, or act on that object.
- Metrics support decisions; they do not replace the object.
- Sidebars and cards must not bury the map/canvas/timeline/roster/table.
- Active navigation changes the visible object, scope, or content.

## Rejected

- Generic dark dashboard/card soup.
- Same-weight panel grids where no object owns the screen.
- Product map/canvas/timeline pushed down or treated as one card among many.
- A dashboard label doing the job of the real product object.
- Panels that look useful but do not change decisions.
