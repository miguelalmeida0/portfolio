# Tempo Loom Mobile Product Success

## Why This Is Approved

Tempo Loom is an approved Design OS dogfood result because it successfully tested mobile product flow without drifting into a cinematic landing page, fake dashboard, or decorative app shell.

It validates:

- mobile product flow
- bottom navigation icons + labels
- functional control UI
- selected states
- useful density
- product clarity
- tactile dark palette
- practical motion/feedback concept
- no cinematic landing-page leakage

## What Works

- Compact mobile frame with readable, repeatable screen rhythm.
- Clear tempo hierarchy: BPM dominates without swallowing the whole product.
- Count-in and time controls are visible, selectable, and product-specific.
- Persistent selected states clarify current count-in, time signature, loop, cue, and nav destination.
- Semantic bottom nav icons reinforce labels without replacing them.
- Visible active states make the current screen and current selection obvious.
- Add cue action is differentiated from content through a distinct action treatment.
- Product-specific copy stays truthful: no fake audio analysis, no fake AI claims.
- Settings and saved sets feel like the same product family as practice and loop screens.
- Dark palette supports rehearsal/rhythm focus without becoming terminal-green or dashboard-like.

## What To Transfer

- Product controls before decoration.
- Mobile-first hierarchy with one clear screen job at a time.
- Bottom nav with icons and labels.
- Stateful chips, buttons, and rows that persist selection.
- Clear selected-state language using surface, outline, accent, and text weight.
- Practical density: many useful controls visible without feeling cramped.
- Consistent screen family across practice, loops, record, sets, and settings.
- Local product truth: copy admits the demo is visual/silent instead of pretending to analyze audio.

## What Not To Copy Blindly

- Do not reuse exact colors for every mobile app.
- Do not force dark theme for every app.
- Do not use this as a landing-page pattern.
- Do not use the exact same bottom nav shape everywhere.
- Do not assume every mobile product needs a big BPM display.

## Design OS Rules This Validates

- Mobile bottom navigation icon + label rule.
- Selectable state persistence.
- Modal/sheet safety by avoiding clipped overlays in the captured success state.
- Add-action differentiation.
- No forced brand chrome.
- No decorative orbital overlays.
- No cinematic leakage into product UI.
- Useful motion over decorative motion.
- Product truth over fake AI/audio claims.

## Benchmark Value

Mark this as a gold reference for:

- mobile product
- functional control UI
- selection-first UX
- music/rehearsal utility
- compact stateful product UI

This is not a visual pattern to clone blindly. It is a benchmark for interaction clarity, statefulness, mobile product craft, and Design OS rule convergence.
