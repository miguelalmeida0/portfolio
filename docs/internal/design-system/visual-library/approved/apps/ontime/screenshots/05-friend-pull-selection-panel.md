# Friend Pull Selection Panel

## Status
Approved app reference

## Visual summary
The screen shows a friend-selection flow with an avatar rail, a large image/profile card, suggested invitation copy, and actions to deal again or send. It centers one friend as the focal object while keeping other people available for switching.

## What Migi likely likes
- Composition: horizontal friend rail feeds into one large profile/action panel.
- Hierarchy: selected person, suggested plan, tags, and CTA are easy to parse.
- Spacing: the large central panel feels calm and app-like, not like a list.
- Typography: bold names and invite text make the social choice concrete.
- Materials/colors: cream background, warm image, coral CTA, and soft status chips.
- Interaction/product pattern: select person, review suggestion, customize, send.
- Emotional tone: personal, low-pressure, and warm.

## What future agents should copy
- For selection-first social flows, make the selected person or object the hero.
- Keep alternatives visible in a rail without crowding the detail panel.
- Show what will be sent before the user commits.
- Use action language that matches the social context.

## What agents must not copy blindly
- Do not copy face imagery, friend names, or exact message copy.
- Do not use fake portraits or availability unless clearly sample-labeled.
- Do not make friend selection image-led without asset hygiene.
