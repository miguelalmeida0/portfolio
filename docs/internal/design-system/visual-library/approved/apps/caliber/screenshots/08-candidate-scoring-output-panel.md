# Candidate Scoring Output Panel

## Status
Approved app reference

## Visual summary
The screen shows candidate rewrite results with a picked winner, overall score, category metrics, risk label, and actions to use or copy the selected version. It makes automated selection auditable by showing why the winner was chosen.

## What Migi likely likes
- Composition: winning result first, then scored alternatives.
- Hierarchy: selected output, action buttons, score, metric chips, explanation.
- Spacing: stacked candidate cards support comparison without table density.
- Typography: readable prose paired with compact score labels.
- Materials/colors: dark cards, blue selected outline, muted metric chips.
- Interaction/product pattern: inspect candidates, choose winner, copy or apply output.
- Emotional tone: accountable, transparent, and editorial.

## What future agents should copy
- Show why an automated output was selected.
- Put user actions directly on the winning candidate.
- Break evaluation into understandable dimensions.
- Label fallback scoring honestly when used.

## What agents must not copy blindly
- Do not invent scores, metrics, or fallback claims.
- Do not copy sample prose or author-specific language.
- Do not use scoring UI if users cannot understand or challenge it.

## Best use cases
AI evaluation, candidate comparison, writing tools, recommendation systems, output selection
