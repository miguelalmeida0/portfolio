# Atlas

## Status
Approved app reference

## What Migi likes
- A one-action product surface with a giant question, one big input, and very little decoration.
- Light grid texture, quiet icon rail, and large rounded input surface that make code intelligence feel approachable.
- Honest empty/no-issue states that explain what happened and what to do next.
- Mobile adaptation that preserves the same primary action instead of becoming a separate product.

## What future agents should copy
- When a product has one primary action, make it unmistakable.
- Keep examples and history secondary to the main input.
- Use empty states to explain product truth, not to decorate absence.
- Preserve hierarchy across desktop and mobile.

## What future agents must not copy blindly
- Do not copy Atlas branding, repo/example text, or code intelligence claims.
- Do not use a giant input for products that require browsing or comparison first.
- Do not copy mobile capture artifacts or bottom-left control overlays.
- Do not imply code analysis works unless the loop is implemented.

## Scope
Global for single-action tools; app-specific for code intelligence.
