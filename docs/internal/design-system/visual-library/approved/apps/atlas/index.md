## Reusable Patterns

- One-action tools should not pretend to be dashboards.
- Empty states should explain outcome and next step.
- Mobile should preserve the task hierarchy.
- Example chips can reduce blank-input friction.

## App-Specific-Only Patterns

- Code intelligence copy and Atlas branding.
- Repo URL/snippet examples.
- Green status dot and specific icon rail.

## Top Approved Directions

1. Minimal input-first experience.
2. Honest empty-state explanation.
3. Responsive single-action hierarchy.

## Warnings For Future Agents

- Do not imply code analysis works unless the loop is implemented.
- Do not copy mobile capture artifacts.
- Do not force this sparse layout onto selection-first products.
