# Cascade Lab Robotic Dashboard And Information Architecture Failure

## Verdict

Rejected execution.

## Why This Matters

This failure is not primarily overlap, clipping, empty space, or responsiveness.

The problem is deeper: the screen immediately reads as AI-created because the palette is dull and robotic, and the information architecture tries to hold too many processes on one page instead of using focused navigation routes.

## What Failed

- Dull AI-default dark dashboard palette.
- One-note blue-grey/cyan technical color language.
- Panels and controls share too much of the same surface/material weight.
- Too much operational information appears in one page.
- Navigation exists, but the UI still feels like a single dense pileup.
- Workflows that deserve separate routes are compressed into one command surface.
- Abstract labels and technical-sounding surfaces replace real user tasks, realistic records, and domain-specific page jobs.
- The result does not approach the approved elite dashboard inspiration in `visual-library/approved/inspiration/01-command-centers-dashboards/`.

## Required Future Prevention

- Use `design-dna/human-dashboard-palette-rules.md`.
- Use `design-dna/dashboard-route-architecture-rules.md`.
- Inspect approved dashboard inspiration before dashboard implementation.
- Define route map and task inventory before layout.
- Define a Domain Content Contract before visual spec: real entities, route jobs, mock data schema, realistic records, metrics, units, statuses, and source/freshness labels.
- Define human/reference-driven dashboard palette before tokens.
- Compare final dashboard against approved references for palette, density, material range, route focus, and attraction zone.
