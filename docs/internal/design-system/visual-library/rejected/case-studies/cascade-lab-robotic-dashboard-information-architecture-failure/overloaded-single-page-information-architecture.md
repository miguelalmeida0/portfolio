# Overloaded Single-Page Information Architecture

Cascade Lab exposes too many processes in a single page.

Operational products need route architecture. A good nav system is not decoration; it divides work into manageable decision spaces.

## Failure Signs

- overview, traces, services, hypotheses, blast radius, decision log, rollback, and mobile concepts appear as one massive page
- side nav exists, but content still feels like a single overloaded canvas
- users must parse many unrelated processes at once
- dense product tasks are not split into focused routes
- mobile view is treated as another content area rather than a real compact route/mode

## Future Rule

For complex dashboards, create a task inventory and route map before layout. Each route must have one primary job, one primary user question, and a bounded information set.
