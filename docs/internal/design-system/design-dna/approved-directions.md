Use this file to record directions Migi explicitly approved. Do not infer approval from a generated screenshot, implementation progress, or lack of immediate rejection.

Record approved directions with:

- project or feature

- visual metaphor
- composition
- focal object
- emotional hook
- what remains hidden

## Approved: Artistic Landing Page

An artistic landing page behaves like a visual statement, not a normal SaaS homepage.

What works:

- dominant hero image or scene
- minimal but sharp copy
- asymmetrical or lightly structured composition
- strong use of atmosphere
- restrained UI chrome
- image and typography carry the identity
- sections feel curated, not templated
- visual rhythm continues after the hero

Future-agent rule:

When using landing-page or creative references, preserve the image-led mood across the whole screen. Do not only make the hero artistic and then fall back to generic content sections.

## Approved: Reference Folder Modes

When Migi points to a visual-library folder, the folder activates a design mode. The agent must select the mode before layout, write `docs/design/reference-usage-report.md` for visual-heavy work, and prioritize the strongest references instead of blending every screenshot equally.

### Command Center / Dashboard Mode

Use command-center and dashboard references to build dense but readable tools with clear hierarchy, meaningful metrics, and command/action clarity. The approved direction is not "more widgets"; it is controlled operational focus.

### Artistic / Creative Mode

Use creative, experimental, editorial, and visual-heavy references to create art-directed composition, a memorable first impression, unusual rhythm, and fewer elements with more impact. Image, type, and space are the design material.

### Landing Page / Poster Mode

Use landing and hero-page references for image-led composition, sparse copy, poster-like first screens, emotional scenes, minimal chrome, and visual rhythm beyond the hero.

### Mobile Product Flow Mode

Use mobile app references for strong mobile hierarchy, real flow, thumb-friendly actions, polished navigation/card systems, and readable layouts. Beautiful stills are not enough; the screen must imply a usable product flow. Strong mobile product UI also proves sheet fit, icon+label bottom navigation, persistent selected states, distinct add/create affordances, and control indicators that never collide with labels.

### Selection / Gallery / Browse Mode

Use selection, gallery, roster, marketplace, media-library, and configurator references to create desire to click/select, a strong selected state, preview/detail relationship, browse rhythm, and object hierarchy.

## Approved: Image-Aware Dashboard

Migi's dashboard references are not plain admin panels. They are useful command surfaces with at least one memorable visual attraction zone: a dominant chart, 3D/isometric scene, product object, media block, stacked card object, character/avatar cluster, or rich content focal point.

What works:

- one strong visual anchor that gives the dashboard gravity
- graph-rich data surfaces that feel designed, not pasted in
- deliberate use of imagery, objects, avatars, media, scenes, or product visuals
- useful metrics, queues, controls, and lists arranged around the anchor
- varied panel sizes and functions instead of equal card repetition
- compact but readable scale with several meaningful objects visible quickly
- soft premium shells, refined pills/chips, subtle depth, and calibrated spacing
- controlled typography that creates hierarchy without giant headings

Future-agent rule:

For dashboard work from `01-command-centers-dashboards`, define the attraction zone before designing the grid. If the screen has no memorable focal object, scene, media block, dominant chart, or equivalent visual gravity, the dashboard is not using Migi's references correctly.

## Approved: Art-Directed Command Surface

A strong dashboard can be operational and expressive at the same time. The command surface should feel composed: dense zones, calm zones, visual storytelling, useful controls, and charts that behave as part of the layout.

What works:

- dashboard as a composed surface, not a stack of admin modules
- clear contrast between utility-heavy panels and visual/content-led panels
- asymmetry where it clarifies priority
- charts embedded as visual material and decision support
- navigation that stays restrained while the content surface carries identity
- action modules placed near the objects or decisions they affect
- meaningful status chips and segmented controls with polished interaction grammar

Future-agent rule:

Do not reduce dashboard references to dark mode, cards, charts, and rounded corners. Extract the composition system: attraction zone, panel taxonomy, chart forms, image/object roles, control placement, density, and calm/busy rhythm.

## Approved: Focal-Object Dashboard Hierarchy

The best dashboard references avoid same-weight card fields by giving one area special visual priority. The focal object can be a chart, product visual, venue scene, media cover row, account card stack, AI/chat panel, map, timeline, or selected object.

What works:

- one major focal zone plus supporting panels
- supporting panels that differ by function: metrics, queue, list, chart, content, control, activity
- the primary object/action is obvious without relying on a generic page title
- visual hierarchy comes from scale relationships, placement, contrast, content type, and imagery
- dense information remains scannable because panels do different jobs

Future-agent rule:

Every dashboard concept must name its focal zone and explain how other panels support it. If everything is equally important, nothing is important.

## Approved: Dense But Designed Operations UI

Dashboard density should feel rich, not cramped. Migi's references show a lot quickly, but they use grouping, hierarchy, and varied rhythm so the surface remains readable.

What works:

- multiple useful chart forms visible on desktop
- operational lists, queues, or tables with meaningful state
- compact labels and measured body type
- containers sized to their content
- charts, metrics, and imagery balanced rather than inflated
- one or more calm areas that prevent the dense zones from becoming noise

Future-agent rule:

Dashboard work must deliver useful volume quickly. Do not solve "premium" by enlarging every card, heading, chart, and gap.

## Approved: Dashboard As Composed Surface, Not Card Grid

The dashboard folder teaches composed surfaces. Cards are allowed, but the layout should not be a field of interchangeable rectangles.

What works:

- panel scale variation
- one dominant stage or visual/data object
- supporting rails, queues, tables, and action clusters
- image/content panels that earn their role
- charts treated as authored visualization, not decoration
- a screen rhythm that moves from anchor to supporting evidence to action

Future-agent rule:

Use cards as instruments, not as the concept. If removing the card borders leaves no composition, the design is too weak.

## Approved: Graph-Rich Command Surface

A graph-rich command surface uses charts, metrics, timelines, ranked state, and micro-visualizations as a designed system. The graph layer is useful and beautiful at the same time.

What works:

- one major chart, map, matrix, or visualized state as a clear anchor
- at least two distinct visualization types when dashboard data supports it
- microcharts that improve scanning instead of decorating cards
- charts tied to product concepts, such as priority, freshness, risk, trend, comparison, distribution, or progress
- chart styling that fits the material system and hierarchy
- annotations, states, and labels that help the operator decide what to do next

Future-agent rule:

Do not add charts because dashboards are expected to have charts. Every chart must communicate state, priority, comparison, change, or action pressure.

## Approved: Image-Aware Data Cockpit

An image-aware data cockpit uses images, objects, avatars, media, scenes, or product visuals as meaningful anchors inside an operational surface.

What works:

- image/object/media element creates a focal anchor or product context
- avatars and profile cards show entity context, not tiny decoration
- media covers, product images, scene previews, maps, or object renders make the dashboard memorable
- visual anchors support hierarchy without becoming landing-page hero images
- image panels have a clear role: attraction zone, proof object, media/content preview, product object, status visualization, live tile, or environment mini-map

Future-agent rule:

Small avatars are not enough when references show stronger image/object systems. If imagery is present, it must do real hierarchy or comprehension work.

## Approved: Lively Dashboard Surface

A lively dashboard surface feels active through stateful visual behavior without becoming chaotic.

What works:

- live indicators that communicate freshness or monitoring state
- animated chart transitions or progress movement
- timeline/state strips that show change
- hover and selected states that clarify focus
- optional animated/live tiles when they have a product role
- motion used for state, selection, freshness, progress, or activity

Future-agent rule:

If the product represents live signals, monitoring, activity, or operational freshness, the dashboard should not feel dead. Motion is optional, but state energy is not.

## Approved: Mixed-Material Dashboard

A mixed-material dashboard uses varied surfaces instead of one repeated panel style.

What works:

- base surface, raised panels, quiet panels, active panels, image/media panels, and data panels
- palette range across neutral surfaces, state colors, and controlled accents
- material contrast that clarifies hierarchy without making the UI noisy
- accent color used selectively, not everywhere
- light, dark, mixed, glass, soft neutral, editorial, or image-driven palettes chosen from references and product context

Future-agent rule:

Do not let the dashboard become one muddy color wash. Palette and material range must make hierarchy clearer.

## Approved: Clear Navigation Language

Navigation should feel immediately legible. Labels can be compact, but users should not have to decode internal abbreviations or developer shorthand.

What works:

- plain labels such as Command, Signals, Compare, Brief, Intake, Memory, Genome, or Rulebook
- compact labels that are still obvious in context
- icon-only moments only when paired with tooltips, clear adjacent labels, or universally understood symbols
- selected states that make the user's location obvious
- responsive nav that preserves comprehension instead of compressing everything into mystery pills

Future-agent rule:

If a nav label needs a glossary, it is not ready. Style can compress navigation, but it cannot sacrifice meaning.

## Approved: Crafted Responsive Navigation

Responsive navigation should feel intentionally designed at every width, not squeezed down from desktop.

What works:

- desktop top nav, side rail, or hybrid chosen for the product
- tablet nav that preserves spacing and label readability
- mobile bottom navigation by default for applications with 3+ primary destinations
- compact top navigation only for documented exceptions: documentation sites, desktop-first enterprise tools, editor software, or scrolling-first websites
- bottom nav with balanced spacing, touch-safe targets, clear labels, meaningful icons, excellent icon/text alignment, safe-area support, and visible selected state
- nav that never overlaps content or becomes oversized pills fighting the layout

Future-agent rule:

Mobile navigation should feel as polished as a strong consumer app, even in a dashboard or command surface. The top of mobile app screens should be reserved for branding, current page title, search, context, or hero imagery, not primary navigation.

## Approved: Composed Navigation System

Navigation should feel intentionally designed for the page's visual world, not pasted on top of it.

What works:

- placement supports the composition
- wordmark, links, and CTA have clear roles
- navigation feels native to the concept
- desktop, tablet, and mobile behavior is planned
- mobile does not receive a desktop link dump
- CTA is visually integrated but still clear
- interaction, focus, and active states feel crafted
- navigation pattern is selected from references, mode, and product needs

Why it works:

It turns navigation into part of the brand experience while preserving usability.

Future-agent rule:

For visual-heavy work, create `docs/design/navigation-strategy.md` before implementation and choose a navigation pattern deliberately. Do not let every direction use the same navbar with different colors.

## Approved: Scan-First Product Panels

Panels should help users scan state quickly before asking them to read.

What works:

- short title
- value or status
- one-line summary
- two or three meaningful chips
- clear action near the object it affects
- expanded detail, drawer, preview, or artifact view for long copy

Future-agent rule:

Do not turn cards into paragraph boxes. Dense products need structure, not prose weight.

## Approved: Human Reference-Driven Palette

A strong palette feels chosen, not generated. It is derived from reference evidence, product mood, imagery, or data semantics.

What works:

- controlled accent roles
- distinct base, raised, quiet, active, image/media, data, danger, and success surfaces
- color used to clarify state and hierarchy
- enough warmth, restraint, or editorial specificity to avoid machine-default blue/grey, terminal green, neon lime, or AI purple

Future-agent rule:

Palette must have an argument. If the color system feels emitted by a template, redo it before calling the UI polished.

## Approved: Expressive Balanced Palette

Description:

A palette that feels original and memorable while still readable, controlled, and conceptually appropriate.

What works:

- surprising but harmonious color relationships
- strong foreground/background contrast
- color tied to the subject matter
- image-compatible tones
- controlled accents
- semantic state colors
- no random rainbow noise
- no generic generated-app mud

Why it works:

It gives the product a visual identity instead of making it look like another template.

Future-agent rule:

For artistic, cinematic, landing, portfolio, creative, editorial, and experimental modes, explore expressive palettes instead of automatically choosing the safest neutral. Bold color is allowed when OKLCH/APCA contrast and readability hold.

## Approved: Polished Functional Dashboard

A dashboard can be working and still not done. Strong dashboard work requires product function plus visible craft.

What works:

- readable navigation
- aligned search/filter/action toolbars
- proportionate buttons
- scan-first containers
- graph richness
- image/object/media layer when references support it
- collision-free responsiveness at 1440, 1280, 1024, 768, and 390
- human palette and varied material surfaces
- no fake live/session/status theater

Future-agent rule:

Treat "functional but unfinished" as a design failure, not a handoff state.

## Approved: P0 Layout Integrity

A visually strong UI preserves structural integrity before it asks to be judged on taste.

What works:

- text stays inside containers
- chart bars, lines, points, axes, and labels stay inside plot/card bounds
- cards preserve readable width or change presentation
- nav remains understandable across desktop, tablet, and mobile
- chips, badges, and pills wrap or truncate intentionally
- forms and buttons stay readable and proportionate
- images and badges do not collide
- labels remain semantic instead of collapsing into fragments
- layouts adapt at breakpoints instead of squeezing the same desktop grid until it breaks

Future-agent rule:

Before visual approval, prove layout integrity at 1440, 1280, 1024, 768, and 390. A broken layout cannot be award-level, no matter how good the mood or palette is.

## Approved: Responsive Adaptation

Responsive design should change structure when the content model requires it.

What works:

- dense desktop surfaces with clear minimum panel widths
- tablet layouts that reduce columns or reorganize panels
- mobile layouts that become prioritized stacks, lists, accordions, or simplified command sections
- charts that resize, simplify, or change form at smaller widths
- secondary metadata that hides behind details instead of crushing labels
- nav that becomes a crafted bottom or compact top system

Future-agent rule:

If content cannot stay readable at a width, change the layout. Do not suffocate the desktop composition until it technically fits but visually fails.

## Approved: Dense But Controlled Scale

Interfaces can feel premium, artistic, or cinematic while still showing meaningful content density. Reference UIs often show many pieces of information at once, but with hierarchy, grouping, and rhythm.

What works:

- several meaningful content objects visible above the fold
- hierarchy through contrast, not only size
- containers sized to content
- typography range: large / medium / small, not all giant
- clear grouping and scan paths
- generous spacing where useful, not empty dead space everywhere
- visual richness without clutter

Future-agent rule:

Before implementing, inspect the selected reference folder and estimate the real scale relationships. Do not default to huge headings and oversized cards just because the design should feel premium.

## Approved: Protected Image-Led Composition

An image-led UI where typography, imagery, and atmosphere work together without sacrificing readability.

What works:

- text has a clear safe zone
- imagery remains emotionally readable
- focal objects are protected
- overlays feel intentional, not like emergency patches
- small labels remain legible
- contrast strategy survives responsive crops
- image and copy feel composed together

Future-agent rule:

When using artistic, landing, or creative references, extract the reference's contrast strategy, not only the visual mood.

## Approved: Immersive Image-Led Scene

The page uses a major image as the visual environment. Text, nav, and actions are placed with restraint so the image becomes the emotional and compositional center.

What works:

- image is the first impression
- text is sparse and carefully placed
- UI chrome is minimal
- image crop protects the focal subject
- image atmosphere defines the page mood
- layout feels composed, not gridded
- text uses safe zones, scrims, masks, or plates for readability
- image continues to influence the page rhythm beyond the hero

Future-agent rule:

If the reference uses a strong background scene, start from the scene. Do not start from a grid and insert an image later.

## Approved: Data-Shape-First Chart Systems

Charts become strong when they answer a product question and match the underlying data shape.

What works:

- chart type selected from trend, comparison, proportion, correlation, intensity, geography, flow, target, forecast, anomaly, hierarchy, network, distribution, finance, real-time, or sentiment data
- explicit accessibility fallback before implementation
- labels, legends, values, and interaction that help decisions
- graph variety in dashboards only when each visualization has a distinct job
- chart bounds planned before responsive implementation

Future-agent rule:

Do not add charts because dashboards are supposed to have charts. Select the chart type from data shape, user decision, volume, accessibility, and interaction need.

## Approved: Taxonomy-Constrained Style Direction

A strong visual style is chosen deliberately, not mixed from random aesthetic keywords.

What works:

- one primary style family
- at most one supporting treatment
- token extraction before CSS implementation
- effects and motion tied to product role
- accessibility, performance, mobile, and conversion fit checked before coding
- mismatched styles explicitly rejected

Future-agent rule:

Use the style taxonomy as a constraint system. Style must support product purpose and selected references, not decorate around weak layout.

## Approved: Image-First Website Translation

For premium websites and landing pages, high-quality section references should drive implementation.

What works:

- large section-specific references
- fresh detail/extraction images when typography or components are unclear
- deep analysis of text, type, spacing, buttons, colors, imagery, and section rhythm
- code that preserves the source composition instead of drifting into generic sections
- clean, readable hero sections with sparse meaningful UI

Future-agent rule:

When visual website quality is central and image generation or strong references are available, generate or select the visual references first, analyze second, and implement third.
## Approved: Tasteful Landing Craft

Landing, portfolio, and marketing pages should feel read, not generated. The agent starts with a design read, chooses a clear system or aesthetic, locks palette and typography, gives every section a job, and uses images as structural material.

What works:

- one visual concept spine across the page
- section rhythm varies without becoming random
- hero is disciplined and fits the viewport
- CTA intent is consistent
- real or generated images carry actual composition
- motion is purposeful and restrained
- small details feel invisible but correct

Future-agent rule:
For landing/portfolio/marketing work, run anti-AI-tell preflight before coding and again before handoff.

## Approved: Purposeful Motion Craft

Motion should make the interface feel responsive, coherent, and alive only where useful.

What works:

- press feedback under 160ms
- popovers grow from triggers
- transitions are interruptible
- movement uses transform and opacity by default
- reduced-motion behavior is defined
- one signature brand moment beats motion everywhere

Future-agent rule:
Every animation needs a reason: feedback, state, spatial continuity, hierarchy, story, explanation, or perceived performance.

## Approved: Choreographed Motion System

Advanced/cinematic/artistic motion works when the whole page is designed in time, not when a static layout receives one animation layer.

What works:

- page and section motion create a story arc
- image and media reveals feel cinematic and concept-specific
- typography motion supports reading rhythm
- navigation/menu states are part of the art direction
- micro-feedback feels tactile but not noisy
- one signature motion moment is supported by quieter motion layers
- reduced-motion behavior preserves meaning
- motion evidence is captured or honestly blocked

Future-agent rule:
When Migi asks for award-level motion, create `docs/design/motion-choreography-plan.md` and score against `evaluation/benchmarks/motion-cinematic.benchmark.md`.

## Approved: Image-Generated Direction Gate

New visual-heavy work starts with three visual north stars before implementation.

What works:

- Safe Refined, Artistic Expressive, and Unexpected High-Character are visually distinct
- generated images are saved locally with a manifest
- direction options analyze composition, palette, typography, imagery, navigation, motion, and risk
- Migi selects a direction or hybrid before coding
- generated images guide art direction without being copied literally

Future-agent rule:
No new visual-heavy implementation before generated/rendered direction evidence exists or Migi explicitly approves a blocked fallback.
