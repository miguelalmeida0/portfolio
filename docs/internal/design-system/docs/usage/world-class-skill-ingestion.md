# World-Class Skill Ingestion

Miguel Design OS now ingests outside skill/reference material as repo-local operating systems, not raw dumps.

## Ingested Systems

### Data Visualization Selection

Path: `skills/data-visualization-selection/SKILL.md`

Use it when a product has charts, dashboards, analytics, BI, monitoring, forecast, map, funnel, network, sentiment, or graph-rich surfaces.

Output artifact:

- `templates/chart-selection-report.template.md`

### Visual Style Selection

Path: `skills/visual-style-selection/SKILL.md`

Use it when a project needs a deliberate visual style direction, token system, effects discipline, or style-fit check against product/audience/reference constraints.

Output artifact:

- `templates/visual-style-selection-report.template.md`

### Image-First Website To Code

Path: `skills/image-first-website-to-code/SKILL.md`

Use it for premium websites, landing pages, hero sections, marketing sites, product pages, editorial/portfolio work, and visually important website redesigns.

Output artifact:

- `templates/image-first-website-analysis.template.md`

## How Future Agents Should Use This

1. Route the task through `AGENTS.md`.
2. Use the smallest relevant skill set.
3. If the task has charts, load Data Visualization Selection.
4. If the task needs a style family, load Visual Style Selection.
5. If the task is a visual website or landing page, load Image-First Website To Code.
6. Fill the relevant report template before coding.
7. Apply existing Design OS gates: reference usage, screenshot QA, scorecard, and done report.

## Hard Principle

These systems do not override Miguel Design OS taste. They strengthen it.

- Chart rules prevent decorative dashboards.
- Style rules prevent random aesthetic soup.
- Image-first website rules prevent generic coded landing pages after a strong visual reference step.
