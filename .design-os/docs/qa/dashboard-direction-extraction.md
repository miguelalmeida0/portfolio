# Dashboard Direction Extraction

This report summarizes the dashboard design language visible in `visual-library/approved/inspiration/01-command-centers-dashboards/`.

These references are not generic admin dashboards. They are composed command surfaces: useful, data-rich, visually memorable, and often anchored by an image, object, scene, or unusually expressive chart.

## Extracted Taste

Migi's dashboard taste is image-aware, graph-rich, dense but readable, and composition-led. A good dashboard in this mode gives the user utility quickly, but it also has one memorable visual attraction zone that makes the surface feel designed instead of assembled.

The references repeatedly combine charts, stats, lists, controls, avatars, media, object cards, product visuals, scene blocks, and action modules. They do not rely on one repeated card component. They use contrast between dense and calm zones so the screen feels rich without becoming grid spam.

## Common Patterns

### Information Density

The screens usually show many meaningful objects above the fold: a main chart or scene, several metrics, filters, a side rail, a table/list, a queue, account/card state, activity, or product browsing objects. Density is compact but not tiny. Text is controlled, with large labels used sparingly and smaller labels doing real work.

### Card Size Behavior

Panels vary in size and function. Some are broad chart stages, some are compact metric tiles, some are narrow queues, some are visual/product cards, and some are control strips. The references avoid every card having the same size, same weight, and same border treatment.

### Panel Types Coexisting

The strongest dashboards mix at least four panel types:

- focal visual or dominant chart
- metrics or score indicators
- operational queue/list/table
- controls, filters, tabs, or command bars
- avatar/user/social proof elements
- product, scene, media, or object imagery
- supporting charts such as bars, rings, progress tracks, heatmaps, maps, and sparklines

### Chart Integration

Charts are not filler. They are compositional anchors or useful supporting instruments. The references use large area graphs, 3D/wireframe data landscapes, funnels, bars, donut/ring charts, progress meters, heatmap blocks, mini trends, map overlays, and score indicators. The chart styling is integrated into the visual material of the surface.

### Imagery And Object Use

Imagery appears as:

- a 3D/isometric venue environment
- a card stack or payment object
- media covers and artist portraits
- product/equipment objects
- pet/product fragments inside metric cards
- avatars and participant clusters
- promotional image blocks
- visualized data landscapes

This imagery is deliberate. It creates hierarchy, product clarity, or memorability. It is not random decoration.

### Focal Point Creation

Most references create an attraction zone: a large chart, isometric scene, media row, stacked card object, video call panel, product browse surface, or AI/chat overlay. This gives the dashboard visual gravity. The surrounding controls and metrics support that anchor.

### Navigation Treatment

Navigation is present but rarely the star. It is usually a restrained side rail or top segmented control. The dashboard identity comes from the content surface, not from a heavy admin sidebar.

### Soft Versus Sharp UI

The references lean soft and premium: rounded shells, pill controls, translucent overlays, subtle depth, spacious but calibrated gutters, and polished icon buttons. They are not flat terminal panels, but they also avoid childish oversized softness.

### Hierarchy Without Giant Hero Text

Hierarchy comes from panel scale, chart dominance, imagery, contrast, color accents, spatial grouping, and interaction controls. Headings are not inflated to create drama. Dashboards should deliver useful volume quickly.

### Beauty And Usefulness

The best references balance visual storytelling with operational purpose. The screen can look cinematic, playful, finance-heavy, media-led, or product-led while still showing usable data and controls. Beauty does not replace utility; it organizes and elevates it.

### Palette Discipline

The references do not collapse into one muddy dark color. Some are light premium, some dark premium, some mixed light/dark, and some use vivid editorial or object-driven color. Accent color is controlled. It marks active state, selected data, primary action, or critical status; it is not sprayed across every border, icon, chart, label, and button.

Dashboard palettes need material range: base surface, raised panel, quiet panel, active panel, image/media panel, data panel, and primary action surface. This range keeps the dashboard lively while preserving scanability.

### Graph System Richness

The references are graph-rich. They use major charts and supporting micro-visualizations together: line/area charts, bars, rings, progress tracks, heatmaps, timelines, maps, score indicators, ranked rows, and sparklines. Graphs create visual energy only when they communicate product state, priority, comparison, freshness, change, risk, progress, or action pressure.

### Media, Object, And Live Visual Energy

The references often use image/object/media anchors: venue scenes, product images, card stacks, media covers, avatars, profile panels, maps, and visualized data landscapes. Tiny avatars alone are not enough when the reference language is object/media-rich.

Many dashboard references also imply activity. Elite dashboards can feel alive through chart transitions, live indicators, timeline strips, active-state controls, progress movement, or animated/live tiles. Motion is not decoration; it should communicate freshness, progress, selection, monitoring, or activity.

## What Current Signal Desk-Style Outputs Got Wrong

The failed direction drifted into generic software defaults:

- terminal-like dark surfaces without enough premium visual material
- repeated rectangular panels of similar weight
- weak visual contrast between primary and supporting zones
- not enough graph richness or chart variety
- text-and-metrics-only dashboard logic
- too much copy inside panels
- no memorable object, scene, media, or dominant chart anchor
- low information density caused by oversized cards, headings, and padding
- charts treated as generic decorative widgets instead of useful designed instruments
- utility-only layout with no attraction zone
- insufficient reference fidelity: it copied "dashboard" and "dark" but missed composition, focal object strategy, and panel diversity

## Signal Desk Dashboard Retest Lesson

The later Signal Desk dashboard pass improved structure and density, but still failed the dashboard-reference taste test.

Observed failures:

- color scheme became murky green, terminal-like, and lifeless
- dark paneling used too much of one color family
- lime/accent color was overused until hierarchy weakened
- graph system was too limited
- main chart looked decorative and unclear
- imagery was barely used
- dog/image element became a tiny avatar instead of a meaningful visual anchor
- panels had similar material and visual weight
- dashboard felt functional but not award-level

Design OS patch required:

- Dashboard Palette Strategy must be mandatory.
- Graph System Strategy must be mandatory.
- Image / Object / Media Strategy must be mandatory.
- Dashboard mode must reject murky monochrome / terminal-green palettes unless references justify them.
- Dashboard mode must reject major charts that are decorative or unclear.
- Dashboard mode must reject tiny-avatar-only media use when references support stronger visual anchors.
- Dashboard mode must include live/state energy when the product represents monitoring, freshness, or activity.

## Latest Signal Desk Dashboard Craft Failure

The next pass changed direction and started feeling more like a real product surface, but it was still not close to finished. The failure moved from broad dashboard structure into global UI craft.

Observed failures:

- navigation/sidebar labels were unreadable or cryptic: `SD LOCAL`, `CMD`, `SIG`, `CMP`, and `BRF` required decoding
- the top search input and action buttons did not share a clean toolbar baseline or height system
- too many containers held heavy explanatory copy instead of scan-first state
- some buttons became clumsy full-width bars, such as a long generate-brief action that dominated more than its role deserved
- containers, pills, and controls overlapped or collided during resizing
- fake `session-only`, `live`, glowing status dots, and monitoring chips created AI-slop product theater
- responsive navigation did not become a polished mobile/lower nav with clear labels, spacing, and selected state
- the palette still felt robotic, dull, or machine-made rather than human and reference-driven
- the dashboard had product direction, but still felt like a start product rather than a polished design

Design OS patch required:

- add No Cryptic Navigation as a global rule with hard score caps
- require Crafted Responsive Navigation for desktop, tablet, and mobile
- require Toolbar Alignment Strategy for search, filters, and action groups
- require Container Text Weight Limit so panels stay scan-first
- require Button Proportion Discipline so desktop buttons do not become huge bars without reason
- treat Responsive Collision as a hard visual failure at 1440, 1280, 1024, 768, and 390
- reject Fake Live / Session Status Slop unless state is real, understandable, and decision-relevant
- strengthen Human Palette Direction so dashboards do not default to robotic/generated color
- state that Dashboard Is Not Done When It Is Merely Functional
- add these sections to `docs/design/reference-usage-report.md`: Navigation Strategy, Toolbar Alignment Strategy, Text Density Strategy, Button Proportion Strategy, Responsive Collision Checks, and Palette Direction

## Latest Signal Desk Layout Integrity Failure

The following pass exposed a more severe issue: the dashboard direction improved, but structural layout integrity failed. This is P0, not taste.

Observed failures:

- text came out of containers
- card titles were clipped or cut off
- chart bars ran outside their containers into neighboring cards
- containers became too thin on resize
- text inside squeezed containers became unreadable
- labels collapsed into meaningless fragments such as `C`, `U`, or `?`
- image badges overlapped each other
- navigation became oversized and unpolished on resize
- responsive layout failed outside the default viewport
- the dashboard still looked junior compared to polished dashboard references

Why this matters:

The dashboard references show polished containment and responsive control. Dense dashboards can be visually rich, but they still maintain card bounds, chart bounds, readable labels, and deliberate breakpoint behavior. If the UI only works at one viewport, it has not passed visual QA.

Design OS patch required:

- add P0 Layout Integrity as a global rule
- add Content Escaping Containers and Squeezed Card Garbage as anti-patterns
- require Chart Bounds Discipline and Semantic Label Integrity
- require Responsive Adaptation, Not Squeezing
- require `Layout Integrity Contract` and `Responsive Breakpoint Proof` in `docs/design/reference-usage-report.md`
- require checks at 1440, 1280, 1024, 768, and 390
- cap escaped text/charts at 2/10, overlapping containers at 3/10, clipped card content at 4/10, and one-viewport responsiveness at 5/10

## Future Agents Must Do Differently

Before coding dashboard work from this folder, agents must define:

- the attraction zone or focal visual anchor
- the panel mix: metrics, charts, queues, lists/tables, media/object blocks, actions, controls
- the chart forms and what each one helps decide
- the palette strategy and accent discipline
- the graph system: major chart, supporting charts, microcharts, and purpose
- the image/object strategy and why each image earns its place
- the material range across surfaces
- the live/motion strategy when the product represents activity
- the density target and visible content count above the fold
- the calm zones versus busy zones
- the typography scale relationship
- the way hierarchy is created without making everything huge
- navigation labels and responsive nav behavior
- toolbar alignment for search, filters, and actions
- panel text density and progressive disclosure
- button proportion rules across desktop and mobile
- collision risks at 1440, 1280, 1024, 768, and 390
- minimum card widths and breakpoint behavior at 1440, 1280, 1024, 768, and 390
- chart containment strategy, including plot bounds, label margins, and responsive chart variants
- text truncation, line-clamp, and long-content behavior
- chip/pill wrapping and image/badge collision prevention
- how labels remain semantic instead of collapsing into nonsense
- why live/session/status indicators are real and useful, or why they are omitted
- why the palette feels human and reference-driven instead of robotic

Agents must not answer these references with "dark mode plus cards plus charts." The correct direction is an art-directed command surface: dense, useful, graph-rich, image-aware, palette-disciplined, materially varied, lively when state is live, varied in hierarchy, and visually memorable.

## Compact Operating Paragraph

Dashboard mode in Miguel Design OS means an image-aware, graph-rich, composition-led command surface: start with one memorable attraction zone, then arrange metrics, charts, queues, imagery/content, controls, and actions around it with varied panel weights, compact controlled scale, useful data visualization, palette discipline, mixed material surfaces, optional live/state energy, and a clear rhythm between dense and calm areas. Navigation must be understandable, responsive nav must be crafted, toolbars must align, panels must be scan-first, buttons must be proportionate, resize collisions are blockers, status chips must be real, and palette must feel human/reference-driven. P0 layout integrity is non-negotiable: text stays inside containers, charts stay inside bounds, cards remain readable, labels remain semantic, badges do not collide, and the dashboard adapts at 1440, 1280, 1024, 768, and 390. Never ship same-weight card soup, murky terminal-green panels, single-accent overuse, text-and-metrics-only admin layouts, oversized empty dashboards, decorative charts, image-starved surfaces, fake status theater, cryptic navigation, squeezed card garbage, chart overflow, or a dashboard with no focal visual gravity.
