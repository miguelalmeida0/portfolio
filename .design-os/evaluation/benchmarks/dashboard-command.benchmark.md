# Dashboard Command Benchmark

## Purpose

Tests whether dashboard and command-center work becomes graph-rich, image-aware, dense but readable, and visually memorable instead of generic admin panels.

## What gold examples prove

- Composition: one attraction zone plus varied supporting panels.
- Palette: reference-driven material range, not murky monochrome terminal UI.
- Typography: compact controlled type with readable hierarchy.
- Image/object/media use: visual anchors, objects, maps, media, or scene blocks can support dashboard memory.
- Motion: live/state motion is useful only when it communicates freshness, selection, or progress.
- Density: several useful objects visible quickly without card squeeze.
- Responsive behavior: multi-column desktop adapts into prioritized sections.
- Interaction quality: nav, filters, charts, queues, and actions are understandable and aligned.

## What rejected examples prove

- Same-weight card soup caps dashboard quality.
- Decorative live/session indicators are AI slop.
- Chart overflow and text escaping containers are P0 failures.
- Cryptic navigation makes dashboards feel unfinished.
- Text-heavy panels kill scanability.

## Hard failure signs

- No meaningful chart system.
- No dashboard attraction zone.
- Graph-lite despite graph-rich references.
- Image/object/media layer absent when references support it.
- Same-weight card soup.
- Fake live/session slop.
- Decorative chart wallpaper.
- Layout integrity failures.

## Scoring criteria

- Dashboard attraction zone: 15
- Meaningful chart system: 20
- Graph richness and chart bounds: 15
- Image/object/media layer: 10
- Dense but readable hierarchy: 15
- Palette/material discipline: 10
- Layout integrity and responsive adaptation: 10
- Screenshot evidence and done report: 5
