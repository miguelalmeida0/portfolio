# Watchlist Coverage Board

## Status
Approved app reference

## Visual summary
The screen shows a watchlist coverage board with tabs for different research scopes, a dense security table, and a right-side panel of tracked symbols. It makes coverage state visible while preserving terminal row density.

## What Migi likely likes
- Composition: main data table paired with a research-detail side panel.
- Hierarchy: selected watchlist, coverage board, table rows, then symbol chips.
- Spacing: clear columns and row dividers keep a dense dataset organized.
- Typography: compact ticker labels, bold names, and numeric columns.
- Materials/colors: dark panels, thin borders, green active underline, muted gray labels.
- Interaction/product pattern: switch coverage scope, inspect tickers, scan quote/news coverage.
- Emotional tone: focused, technical, and research-oriented.

## What future agents should copy
- Pair dense lists with an inspector/detail panel when the user needs context.
- Use tabs to switch data scopes without moving the table structure.
- Keep identifiers such as tickers visually compact and repeatable.
- Label unavailable or pending data honestly.

## What agents must not copy blindly
- Do not copy watchlist names, ticker symbols, quote data, or news counts.
- Do not use ticker-chip grids unless identifiers are central to the product.
- Do not hide missing data behind decorative blank states.
