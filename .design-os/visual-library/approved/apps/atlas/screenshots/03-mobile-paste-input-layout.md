## Visual summary
The screen shows the Atlas primary input experience adapted to a narrow mobile viewport. The same headline, product label, large paste area, and example chips remain visible, though the screenshot includes capture/crop artifacts near the top and bottom.

## What Migi likely likes
- Composition: the primary input remains centered and dominant on mobile.
- Hierarchy: label, headline, subtitle, input, and examples retain desktop order.
- Spacing: large vertical gaps prevent the page from feeling cramped.
- Typography: headline and helper text remain oversized but readable.
- Materials/colors: light grid texture and white input surface continue the desktop identity.
- Interaction/product pattern: mobile paste entry with example chips.
- Emotional tone: simple, focused, and portable.

## What future agents should copy
- Preserve the same primary action across mobile and desktop.
- Let large controls stay large on mobile when the task is input-first.
- Stack examples below the input without cluttering the first read.
- Test crop and viewport edges before using mobile screenshots as QA proof.

## What agents must not copy blindly
- Do not copy top/bottom capture artifacts or bottom-left overlay.
- Do not let mobile hero type push the core input below reach.
- Do not assume every desktop layout should simply scale down.
