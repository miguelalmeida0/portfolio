# Plan Grid Filter System

## Status
Approved app reference

## Visual summary
The screen shows a plan archive/grid with status filters, category counts, and repeated plan cards. Cards encode time, place, membership, and action state while keeping the overall page playful and readable.

## What Migi likely likes
- Composition: large page heading, filter bar, then a three-column plan grid.
- Hierarchy: status filters make the plan list immediately understandable.
- Spacing: card gutters and large radii keep the grid soft despite repetition.
- Typography: bold card titles and smaller metadata support quick scanning.
- Materials/colors: pastel cards vary state without becoming chaotic.
- Interaction/product pattern: filter plans, open room, inspect participant state.
- Emotional tone: organized, friendly, and alive.

## What future agents should copy
- Use filters with counts when the product has meaningful states.
- Make repeated cards visually consistent but state-aware.
- Keep the primary action in a stable corner for every card.
- Use color to encode state only when labels also explain it.

## What agents must not copy blindly
- Do not copy fake plan data, people, venues, or counts.
- Do not create a card grid if the product needs a single focused action.
- Do not let pastel color become the only state indicator.

## Best use cases
social planning, event lists, state-filtered grid, community plans, lightweight dashboard
